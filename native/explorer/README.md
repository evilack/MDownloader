# MDownloader common helper (Windows)

The former Explorer bridge is now the common Windows helper. Version 9 executes an extension-delivered source package using a bounded, generic file manifest. The extension chooses feature versions and workflows; the body checks origins, safe paths, hashes, locks and process ownership. It does not contain a speech-module filename list. Its own runtime is Windows-supplied PowerShell; Python/engines are prepared privately only on requested setup. Ordinary browser downloads still use Chrome's downloads.show. The native name com.mdownloader.explorer, ExplorerBridge directory, allowed origins, installation identity and folder links are retained.

Options → Local automatic captions → **Install captions** delivers the current package through installCaptions; captionSetupStatus reports the requested installer process. The extension verifies the actual execution protocol after setup. The body accepts up to 128 safe relative files and one MiB decoded source, including nested modules; adding a feature module does not require updating the body. Version 8's fixed filename contract needs one migration to version 9. No caption CMD is downloaded or opened. Models remain opt-in. See [current responsibility and verification record](../../docs/command-only-helper-verification-2026-11-10.md).

Setup uses an origin/job-owned atomic state and Windows process job: a terminated worker also terminates its bootstrap descendants. A live setup remains busy regardless of age. Setup and removal coordinate through the same named mutex; stale observers/workers cannot overwrite a successor's state. Interrupted staging cleanup removes only the exact bundled source allowlist, retaining unknown files and media. Common-helper removal retains the separately installed caption engine/models and its native host.

Real Chrome157 with the production options binder, a registered isolated common helper and actual engine installation passed: one install click, zero browser downloads, no downloads permission, real caption connection, no models. The test uses unique temporary native host names and a NoRegister/destination override; existing user helper registrations are untouched. See [verification](../../docs/common-helper-verification-2026-11-09.md).

The normal Windows setup entry is **Settings → Download location → Select folder**. If the helper is absent, **Install** downloads `MDownloader-Windows-Setup.cmd` and immediately requests its execution from that same click. There is no separate extension **Run installer** or **Continue** action. Native ping must succeed before the dialog closes and the original folder picker continues automatically. Cancel keeps the current folder and prevents a late download from requesting execution. Chrome/Windows may still require security confirmation. The current extension ID is embedded automatically. Both package flavors use the same helper; macOS skips this Explorer helper.

The packaged payload is prefetched before the install click to reduce gesture-expiration risk. `downloads.open` is a required extension permission so first-time optional-permission handling does not insert another extension step. A blocked download, failed execution request or connection timeout is an error, never an installed state. **Open downloads** and **Show installer** are recovery controls shown only after an error. Browser download protection remains enabled.

Tests verify a single install click requests download/open and native connection automatically accepts the folder gate. Real Chrome157 retained user activation and accepted `downloads.open`, but the harmless marker file was not observed executing during the bounded browser probe. Full browser-to-OS installation completion is therefore unverified; OS confirmations may remain. The UI never claims success from a download/open API reply alone.

For maintainers, run node tools/build/build-explorer-installer.mjs first to generate the caption payload cache for a source install. Distribution packages generate their own payloads automatically. Equivalent CLI registration changes the current user's Chrome NativeMessagingHosts registry and copies the helper to LocalAppData\MDownloader\ExplorerBridge. Run only within authorized setup scope:

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\native\explorer\install.ps1 -ExtensionId <actual-unpacked-extension-id>`

On the first reveal for a previously selected folder, choose that saved folder once in the Windows dialog. The bridge checks its leaf name, saved filename, file size, and bounded first/last128KiB fingerprint against the browser-granted file before remembering the binding. Later clicks directly launch SystemRoot\explorer.exe with `/select` on that file. It accepts no client-supplied absolute path, executable, or command. The native messaging manifest restricts callers to explicit extension IDs. Bindings are scoped by extension origin and directory key; they contain local folder paths and remain on this computer.

Settings → Download location now includes **Remove Windows helper** on Windows. Its confirmation explains that helper files/folder links are removed, downloaded videos/subtitles are retained, and the location returns to the browser default. Cancel changes nothing. A legacy installed helper uses the bundled removal CMD; Chrome may require a separate file-execution confirmation.

After verified removal, both active location fields are saved as empty in the existing atomic storage write. The open settings page also resets the save-mode radios and clears its displayed folder without requiring **Apply changes**. Targeted tests cover the storage reset, immediate display reset, reopening settings, and the blocked-download guidance; these checks do not install or remove the real helper.

New installations and upgrades also register **MDownloader Windows Helper** under Windows Settings → Apps → Installed apps, for the current user without elevation. That entry launches the same uninstaller with a native confirmation (No by default). The uninstaller validates its exact LocalAppData\MDownloader\ExplorerBridge root, rejects directory junctions and foreign registrations, removes an explicit allowlist of helper files plus folder bindings/lifecycle data, and removes only its own NativeMessagingHosts and Uninstall keys. It removes a directory only if empty. Other files, including media inside that directory, are retained. Completed download records and their browser file handles remain available for playback; the selected location becomes the browser default. The unrelated Kakao helper is not modified.

The native host acknowledges scheduling, then a detached desktop worker waits for the host to exit. Only after file removal and both registry deletions does it send a random installation-identity receipt to the shipped extension lifecycle page. The page matches the stored identity and verifies the native host is absent before resetting both downloadFolder and pickedDownloadFolder in one storage write. A missing host alone never counts as successful removal. Startup/settings focus can retry a received receipt interrupted during consumption. Client routing records the running Chrome executable/user-data root and targets installed profiles; a bounded, shared read of only that extension's recent storage logs covers profiles whose Preferences have not flushed yet. No Chrome databases are edited.

Maintainer command: powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File "%LOCALAPPDATA%\MDownloader\ExplorerBridge\uninstall.ps1". Omit -Confirmed for the normal confirmation. The switch exists for authorized scripted verification. Installed files run under the desktop user context so ordinary Chrome can find the same registration.

The extension keeps a native port alive during the first folder chooser. Fingerprint-read errors remain distinct from connection failures. The chooser uses Chrome’s parent window; subsequent linked-folder actions reveal files directly. Installation/update preserves allowed extension origins and UTF-8 folder bindings. The installer writes in the desktop user context and verifies copied hashes, registry read-back and native ping before reporting success.

Regression tests use `-TestMode` and temporary directories for framing, validation, binding, lifecycle and fingerprint checks. Installed-host, OS-dialog and observed Explorer behavior need a separate authorized browser check. The removal probe changes the real current-user installation and must not be run as an ordinary cleanup check.
