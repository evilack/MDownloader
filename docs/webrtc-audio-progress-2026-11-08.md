# 받은 용량 표시와 WebRTC 음성 저장 — 0.2.31

다운로드 관리자의 활성·일시정지 작업은 진행 수치 자리에 현재 받은 용량을 B/KB/MB로 표시합니다. 라이브 HLS의 조각 수 표시도 받은 용량으로 통일합니다. 진행 바의 비율 계산, 속도, 병합·저장 단계 문구와 완료 작업의 100% 표시는 유지합니다. 같은 설명을 진행 바의 툴팁과 접근성 텍스트에도 적용합니다.

WebRTC의 원격 `track` 이벤트와 SDP 적용 완료는 실제 미디어 수신보다 먼저 발생할 수 있습니다. 기존 수신기는 아직 `muted` 상태인 원격 트랙으로 MediaRecorder를 시작했습니다. Chrome에서 이 순서는 음성 트랙 누락 또는 짧은 무음 AAC를 재현했습니다. 이제 SDP 적용과 수신 트랙의 `unmute`를 모두 확인한 뒤 녹화를 시작합니다. 기다리는 동안 시그널링 응답, 기존 시작 제한 시간과 취소는 계속 작동하며, 종료 시 이벤트 리스너를 해제합니다. 원본 플레이어의 음소거 설정은 변경하지 않습니다.

## G-Velvet 실제 검증

검증 주소: `https://ko.stripchat.com/G-Velvet`.

- 사용자가 제공한 기존 0.2.30 파일(23,140,910바이트)은 AVC 영상 약 32.851초만 있고 오디오 트랙이 없었습니다. 원본 파일은 수정하지 않았습니다.
- 기존 수신 코드를 같은 페이지의 네이티브 WebRTC/MediaRecorder로 실행하면, 녹화기 생성 시 audio/video 모두 muted였고 약 10MB 결과에서 디코딩 가능한 음성은 0.107초의 무음이었습니다.
- 수정된 실제 `webrtc-receiver.js`를 같은 방식으로 실행하여 1280×720 서버 화질을 수신했습니다. 최종 저장 파일은 6,186,412바이트이며 AVC 영상 8.237초와 AAC 음성 8.149초가 포함됐습니다. 브라우저로 저장 전 동일 Blob의 음성을 디코딩한 결과 2채널, RMS 0.08521, peak 0.27271로 무음이 아님을 확인했습니다. 스피커 출력은 사용하지 않았습니다.
- 저장 파일: `C:/Users/evila/Downloads/MDownloader-G-Velvet-audio-0.2.31-test.mp4`. 저장 후 Mediabunny로 실제 디스크 파일의 AVC/AAC 트랙과 길이를 다시 확인했습니다.

이 검증은 실제 G-Velvet 연결에서 수정된 수신 모듈을 페이지의 네이티브 API로 실행한 결과입니다. 설치된 확장 0.2.31의 offscreen 문서와 다운로드 관리자까지의 최종 확인에는 확장 새로고침 후 사용자 조작이 필요합니다. 이전 0.2.30의 탭 종료 후 계속 받기 성공과 이번 음성 검증을 구분합니다.
