# 자막 시간 겹침 자동 보정 및 경고 처리 — 2026-11-11

사용자 지시: 자막 시간 겹침은 자동으로 시간을 맞추고 경고로만 처리한다. 시간 겹침 때문에 음성 인식·다운로드·저장을 실패시키거나 전체 영상을 다시 인식하지 않는다.

## 변경

- 확장이 실제 단어별 인식 시각을 받아 긴 문장을 연결한다. 구간 안의 완전한 문장이 일치해야 한다는 이전 조건을 제거했다. 동일 단어는 시간도 겹치고 일대일 대응이 명확한 경우에만 연결한다. 실제 반복 발화는 일괄 삭제하지 않는다.
- 인식 추정이 서로 다르면 구간 소유권으로 선택하고 표시 시간을 보정한다. 반대 방향 시간 추정 때문에 양쪽 발화가 모두 버려지지 않도록 보완했다. 겹침과 시작 시각 역전도 출력 보정 대상으로 전달한다.
- 단어·문장 텍스트와 실제 원본 시간 범위를 따로 보존한다. 선택한 연속 단어, 0길이 구두점 및 합친 자막의 provenance를 최종 저장 전에 검증한다. 표시 시간 보정은 PCM·디코더의 실제 시간 정보를 변경하지 않는다.
- 경고 문구는 `자막 시간 자동 보정 N건 (경고)`이다. 정상 인식·저장 phase를 유지한다. 구간 병합과 최종 시간 변환의 경고 수는 같은 attempt 안에서 합산하며, 반복 state 전송으로 중복 계산하지 않는다.
- generic `caption_worker_protocol`을 모두 오디오 디코더 문제로 설명하던 문구를 수정했다. 인식 결과 형식, 실제 입력 범위 밖 시각, 단어 정렬 미지원은 별도 오류 코드로 구분한다.

## 실제로 확인한 별도 실패 원인

이전 사용자 실패 입력을 보존한 뒤 medium 모델로 재현했다. 단어 시각 없이 인식하면 첫 30초 입력에서 30.98–32.98초 결과가 나왔다. 같은 입력에 엔진의 단어 시각 계산을 요청하면 유효 범위 안의 결과를 반환했다. 확장은 faster-whisper에 `wordTimestamps: true`를 명시한다.

실제 새 WebRTC 검증에서는 단어 정렬 결과가 NumPy `float64`여서 plain JSON 숫자 검사에서 거절되는 문제도 발견했다. 엔진 어댑터에서 숫자 사실을 Python `float`로 직렬화한 후 기존 유한값·입력 범위 검증을 적용했다. 이 경우를 포함한 네이티브 회귀 검증을 추가했다.

## 책임·배포 경계

단어 시각의 계산과 직렬화만 네이티브가 수행한다. 단어 요청 여부, 병합, 시간 보정, 경고, 이름, 저장 및 완료 판단은 확장이 소유한다. 변경 전 리뷰와 수정 후 독립 재리뷰에서 실행 전용 도우미 경계를 확인했다.

네이티브 기능 패키지는 10이다. 번들을 재생성하고 `--skip-dependencies --no-register`로 설치본에 반영했다. 공통 도우미, 모델, PyAV 및 다른 의존성을 재설치하지 않았다. 독립 리뷰가 소스·번들·설치된 11개 payload의 SHA-256 일치를 확인했다. 확장은 실제 활성 작업이 없는 시점에 다시 불러왔다. 사용자 인식 기본 설정은 변경하지 않았다.

## 자동 검증과 범위

단어 연결·반대 방향 시간 추정·반복 발화·0길이 구두점·시각 역전·원본 범위 검증·전체 finalize/save 경로·UI phase·패키지·HLS 오디오 경계·WebRTC 수신기 JavaScript 64개와 서비스 경고 합산/오류 기록 대상 3개가 통과했다. 네이티브는 실제 NumPy 숫자/단어 시각 3개, 기존 명령 실행기 23개와 PyAV 5개가 통과했다. 시간 역전과 0길이 구두점이 함께 있는 두 경우도 최종 저장까지 검증했다. 전체 저장소 검사를 통과했다고 확대하지 않는다.

음성 전사 자체의 정확도, 수시간 방송, 모든 모델·사이트·macOS를 보장하는 검증은 아니다. 실제 디코딩·입력 손상·실행 실패는 해당 원인으로 보고한다. 자막 표시 시간 겹침을 그런 실패로 분류하지 않는다. 원격 게시·배포는 수행하지 않았다.
