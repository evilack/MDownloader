# 도우미 역할 분리와 확장 소유 음성 런타임

## 사용자 요청

Faster-Whisper에 large-v3-turbo를 추가한다. 도우미의 본체 버전과 음성 기능 버전을 분리하고, 도우미에 앱의 모든 처리를 넣어 기능 변경마다 본체 업데이트를 요구하는 구조를 고친다. 공통 로직을 재사용하고 역할별로 캡슐화한다. 테스트는 실행하지 않는다.

## 책임과 공통 구성

| 구성 | 소유 책임 |
| --- | --- |
| 확장 UI 공통 컴포넌트 | 모델·언어 선택, 출력 형식, 인식 프리셋·개별 설정 |
| 확장 작업·출력 파이프라인 | 영상 수신, 임시 파일, 번역, 자막 삽입, 상태·취소, 최종 파일 저장 |
| 확장 런타임 관리자 | 요구 음성 패키지 판정, 동시 갱신 요청 병합, 앱에 포함된 소스 패키지 전달, 설치 전후 연결 갱신 |
| 공통 도우미 OS 어댑터 | 등록된 확장 인증, 안전한 파일 접근, 전달 패키지 검증·원자적 교체, 설치 작업 잠금·외부 프로세스 실행·상태 보고 |
| 확장 소유 외부 음성 런타임 | Python/CTranslate2 또는 whisper.cpp 실제 인식, 앱이 지정한 모델 관리 실행 |

외부 런타임을 브라우저 내부 실행으로 보고하지 않는다. 외부 실행이 필요한 인식 엔진은 유지하되 코드·모델 레지스트리·업데이트 정책의 소유권을 확장 앱에 둔다.

`common-helper-contract.js`는 도우미 연결 계약을, `caption-runtime-contract.js`는 음성 런타임 준비 조건을 정의한다. 설치 화면·설정·다운로드 창·실행 직전 검사가 같은 조건을 재사용한다. `caption-runtime.js`는 런타임 설치·갱신을 캡슐화하고 동시에 요청된 갱신을 하나로 모은다.

## 버전과 패키지

- 도우미 본체 8은 앱의 소스 패키지를 전달받는 `captionPackageUpdate` API를 추가한 버전이다. 이전 도우미에서 최초 한 번 설치가 필요하다.
- 이후 모델·엔진 옵션 변경은 독립된 음성 패키지 버전으로 관리한다. 현재 음성 패키지는 2다. 본체 버전은 OS 연동·통신 계약을 변경할 때만 올린다.
- 도우미 설치 CMD/PKG에는 음성 엔진 소스 번들을 포함하지 않는다. 확장이 `installCaptions.package`로 현재 패키지를 전송하며, 기존 도우미가 이를 설치한다.
- Windows와 macOS는 기존 설치 잠금·경로 검사·파일 추출·해시 검증을 재사용한다. 본체가 요청을 받을 때와 작업자가 추출할 때 같은 검증 함수를 사용한다. 진행 중 설치에는 패키지를 교체하지 않는다.
- 큰 입력은 설치 패키지 전달 요청에만 최대 1MiB를 허용한다. 나머지 요청은 기존 16KiB 제한을 유지한다.

## 하나의 모델 레지스트리

`native/captions/bootstrap.json`의 `packageVersion`과 `models`가 원본이다. 빌드 데이터 생성기는 이 값으로 확장 메타데이터 모듈을 만들고, 외부 런타임은 설치된 같은 JSON을 읽는다. 모델 레지스트리·표시 이름·지원 엔진·저장소를 UI와 Python에 각각 수동 추가하지 않는다.

large-v3-turbo는 Faster-Whisper만 지원한다. 공식 Faster-Whisper 모델 매핑에 연결된 CTranslate2 모델 저장소의 현재 주소인 `dropbox-dash/faster-whisper-large-v3-turbo`를 사용한다. 기존 크기·진행률·검증·취소·삭제 흐름을 재사용하며 초기 자동 다운로드는 추가하지 않는다.

## 검토 범위

실제 소스와 호출 경로를 정적으로 검토한다. 새 Windows 6파일 번들 및 macOS 4파일 번들의 생성·설치·제거 계약을 함께 맞춘다. 실행 테스트·문법 검사·설치·모델 다운로드·음성 인식·번역 호출은 수행하지 않는다. 설치용 소스 페이로드 데이터만 생성한다.
