# WebRTC 현재까지 저장 누락 수정

요구: 기존 관리자에서 취소 → 현재까지 저장 → 중지 및 저장 버튼을 제공한다. 현재까지 저장은 원래 WebRTC 녹화를 계속하면서 이미 받은 구간을 별도 파일로 내보낸다.

원인: WebRTC 오프스크린 수신기는 snapshotAvailable을 보고하지 않고 CreateTransferSnapshots에 읽기 경계를 등록하지 않는다. SaveCurrentJobOnce 역시 HLS/일반 URL만 처리하므로 UI 조건만 켜서는 저장할 수 없다.

1. 녹화 저장소에서 이미 close된 조각 핸들만 동기적으로 고정한다. 이후 쓰기가 경계에 포함되지 않아야 한다.
2. 기존 CreateTransferSnapshots에 WebRTC 읽기를 등록한다. MP4/WebM prefix를 기존 RemuxFilePrefix로 다시 컨테이너화하여 완전한 패킷만 저장한다. 네트워크 재요청이나 녹화 종료는 수행하지 않는다.
3. 원본 종료/취소 시 진행 중인 부분 저장의 읽기가 끝날 때까지 임시 파일을 보존한다. 부분 저장의 취소 신호와 원본 녹화 신호는 분리한다.
4. 기존 관리자 UI 조건/작업 등록/상태 보고를 연결한다. 별도 부분 저장 작업은 기존 저장 폴더와 MIME에 맞는 확장자를 따른다.
5. 누락 재현 테스트부터 추가하고 저장 경계, 원본 계속 수신, 취소 격리, 실제 음성/영상 prefix 재생을 검증한다. 설치된 UI 검증과 로컬 검사 범위는 구별한다.
