# Model download worker shutdown crash

User reported Tiny at 99.9%, 78.2 / 78.2 MB with caption_model_worker_failed. Read-only inspection of the installed last-model-download.json recorded received=total=78203619 and exitCode=3221225477 (0xC0000005). Windows Application Error event 1000 at 2026-11-10 02:50:16 +09:00 identifies python312.dll in the managed CPython 3.12 runtime. Installed engine.py/host.py hashes matched the current source before this change. No model download, installer or native connection was executed to obtain this evidence.

The source worker left a daemon thread blocked in sys.stdin.buffer.read(1) when the main worker returned. CPython issue #70225 documents interpreter shutdown conflicts for this pattern and recommends a stoppable read loop. That evidence identifies a concrete unsafe lifecycle, but does not prove the precise C stack of this 3.12 access violation. WER report contents are access restricted; no escalation or debugger run was performed.

Implementation: Windows passes inherited handles to the actual parent process and an unnamed cancellation event, then watches with bounded kernel waits. POSIX uses select/read on the owned stdin pipe. The monitor is non-daemon, stopped and joined before interpreter teardown; no background buffered stdin read remains. Parent cancellation signals the owned worker, waits for normal launcher exit, then uses the existing owned-process termination fallback only if necessary. No unrelated process is targeted.

The worker runs with faulthandler directed to an owned staging stderr file. Failures retain unsigned hexadecimal exit code, last phase and sanitized stack locations (file basename, line, function); raw stderr is removed with staging. A nonzero/crash exit still fails even when all bytes arrived. UI distinguishes native runtime crash from ordinary network/model failures. modelDownloadVersion 3 and helper protocol 5 select the updated bundled source and v5 installer links. Existing source JSON writers regenerate the bundled sources after edits.
