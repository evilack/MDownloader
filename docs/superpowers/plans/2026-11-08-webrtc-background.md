# WebRTC 백그라운드 수신 및 HLS 복원

사용자 확정: 원본 페이지를 닫거나 이동해도 WebRTC 수신을 계속한다. 중단은 정상 완료와 구분한다. G-Velvet 등 정상 m3u8 URL도 함께 표시한다. 컴퓨터 사용과 푸시는 하지 않는다.

설계: 원본 페이지의 트랙 복제는 페이지 수명을 넘길 수 없으므로 확장 오프스크린 문서가 별도 WebSocket/RTCPeerConnection/MediaRecorder를 소유한다. 실제 페이지가 보낸 Ristretto connection 및 playStream 정보만 문서/트랙으로 연결해 전달한다. 인증값을 추측하지 않고 디스크나 진단 로그에 저장하지 않는다. 알려진 시그널링 호스트만 허용한다. SDK 원격 실행 없이 표준 WebRTC API와 관측된 프로토콜을 구현한다.

1. WebRTC가 있다는 이유만으로 HLS 전체를 숨기던 필터와 대체 HLS 탐색 금지를 제거한다. 광고/미리보기 역할과 실제 blurred 프로필만 제외한다.
2. 수신 프로토콜 모듈을 독립적으로 구현·테스트한다. 선택 프로필 검증, 첫 수신 확인, 핑 응답, 미디어 정지 감지, 큐 한도, 종료 조각 drain, 취소와 정리를 포함한다.
3. 기존 수신 저장소/부분 저장/관리자에 오프스크린 수신기를 연결한다. 원본 탭 종료 알림은 독립 수신기를 종료하지 않는다. 서버 연결 descriptor가 없으면 명확하게 안내한다.
4. 파일 저장 성공과 수신 종료 사유를 분리한다. 연결 장애 등으로 저장한 부분 파일은 중단 상태에 두고 정상 100% 완료로 표시하지 않는다. 사용자의 중지 및 저장은 정상 완료다.
5. 독립 모듈·통합·회귀 검사 후 실제 G-Velvet의 HLS와 독립 WebRTC 수신을 확인한다. 새 확장 코드 적용이 필요할 때만 사용자에게 새로고침을 요청한다. 원본 페이지 종료 뒤 수신 바이트가 계속 증가하는지 확인해야 한다.
