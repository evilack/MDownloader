# Chrome download notifications

Use chrome.notifications desktop notifications, not chrome.alarms scheduling or custom audio. Add separate opt-in options for completed downloads and actual scheduled-download starts. Both default off; enabling an option requests the declared optional notifications permission from that user gesture. Chrome/OS notification settings control banner/sound delivery.

Completion truth table: notify when no actual side-panel context is open and no visible actual toolbar popup displays that request's item. Notify with both closed or a popup displaying other items. Suppress with a side panel open or that request represented in the popup. Track displayed request IDs (the newest job per candidate), not only popup existence or media key. Items in the popup list count even below its scroll fold. Actual Chrome context types and live popup connections prevent stale/closed UI snapshots from suppressing alarms. A sidebar/ popup HTML opened as a normal tab is not that surface.

Scheduled start always notifies when a scheduled task first receives positive bytes after waiting, independently of the completion visibility rule. Resolving metadata or leaving waiting at zero bytes is insufficient. Completion must use Chrome's owned completed download or successful picked-folder completion, not muxing/progress or interrupted/failed/canceled states. Handle native-complete-before-job-ID-binding and repeated events; persist per-request handled markers across worker restarts. Do not notify unrelated browser downloads, replay old history when options are enabled, store signed URLs, or let notification failure break transfers.

No Computer Use. Use actual development Chrome for UI/context/notification API acceptance; deterministic jobs are explicitly fixtures. Preserve unrelated root work, Store YouTube exclusion, official vendor sources and existing user files. Update docs/evidence/upstream record and local commit only.

Ruling: actual Chrome popup message senders omitted documentId. Switched UI ownership to authenticated live ports, with current-state refresh/acknowledgement at completion and automatic disconnect cleanup. Chrome context types validate surfaces; ordinary popup HTML tabs never register (getViews popup/window check). Worker suspension requires no heartbeat: a completion refresh reopens the port.
