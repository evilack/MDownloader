# 공통 도우미를 통한 자막 설치

사용자가 선택한 방식: 기존 탐색기 도우미를 공통 도우미로 확장하고 Windows 자막 설치 버튼은 동봉 자료를 공통 도우미에서 실행한다. 자막 CMD 다운로드를 사용하지 않는다. 새 설치의 모델은 비어 있고 모델 다운로드는 옵션의 명시적 동작으로 유지한다.

기존 `com.mdownloader.explorer`, ExplorerBridge 위치, 폴더 연결, 설치 ID와 제거 흐름을 보존한다. ping에 기능 버전을 추가하고 고정된 자막 설치/상태 요청만 허용한다. 공통 도우미 설치 패키지가 자막 설치 자료도 동봉한다. 브라우저는 임의 경로나 실행 코드를 보내지 않는다. 설치 작업은 별도 숨김 프로세스에서 진행하고 origin/job ID로 묶인 원자적 상태를 조회한다. 완료 후 실제 자막 호스트 응답을 확인해야 UI가 성공한다.

검토한 대안은 다운로드 CMD(사용자가 제외), 사용자 지정 프로토콜(별도 등록이 필요하며 현재 Native Messaging을 중복), 기존 네이티브 호스트 확장(사용자 선택)이다. 기존 도우미가 없거나 구버전이면 공통 도우미 설치/업데이트를 분명히 표시한다. 이 최초 부트스트랩에는 기존 공통 설치 경로가 필요하며 자막 CMD로 대체하지 않는다. macOS의 기존 PKG 경로는 유지한다.

공통 설치 자료의 파일명/개수/크기/해시를 확인하고 junction 경로 및 다른 확장의 작업 접근을 거부한다. 중복 요청은 같은 작업으로 합치고 실패/중단 상태를 정직하게 표시한다. 공통 도우미 제거는 진행 중인 자막 설치와 충돌하지 않으며 생성된 자막·모델·영상은 보존한다.

검증: 다운로드 API가 없는 브라우저 환경에서 설치 시작→상태→실제 호스트 확인, 구버전/미설치/실패/시간 제한, 실제 PowerShell 프로토콜과 worker, 격리 폴더의 실제 런타임 설치 및 모델 없음, 기존 탐색기/제거 회귀와 전체 테스트. 사용자 PC의 기존 호스트 등록은 시험에서 덮어쓰지 않는다.
