# TVMON HLS 다운로드 진단 및 수정

대상: `https://tvmon1.com/drama/12555/406790251`

## 확인한 원인과 수정

- 플레이어는 `.m3u8` 확장자가 없는 `c.html` 응답을 HLS MIME으로 제공한다. 기존 요청 관측은 URL 확장자가 M3U8인 경우에만 Origin/Referer를 기억하여 해당 응답의 재생 문맥을 잃었다. HTTP(S) 요청 문맥을 제한된 임시 캐시에 보관한 뒤 실제 HLS 응답의 정확한 URL·문서에만 연결하도록 수정했다.
- 재생목록과 영상 조각은 서로 다른 CDN을 사용한다. 실제 플레이어는 같은 조각을 Origin/Referer와 함께 200으로 받았으나 확장 프로그램은 출처 헤더가 없어 403으로 거절되었다. 호스트 접근 권한을 확인한 재생목록의 정확한 자원 URL에 공개 출처와 origin-only Referer를 적용한다. 경로·쿼리가 포함된 Referer는 같은 플레이어 문서에서 성공이 관측된 CDN에만 재사용한다. 쿠키 값은 보관하지 않으며, 쿠키 사용 여부도 실제로 관측한 서버 출처에 한정한다.
- AES-128 identity 키 주소는 16바이트 원시 키 대신 자기 기술형 version 7 JSON 응답을 반환한다. 16KiB 상한, 버전·길이·필수 레이어·순열·Base64·인덱스·패딩 검증을 거쳐 기존 AES 복호화에 전달한다. 응답과 복원 키 바이트는 import 후 지운다. 기존 원시 AES 키와 DRM 미지원 처리를 유지한다.
- 기존 30초 제한은 응답 헤더뿐 아니라 전체 본문 수신에도 적용되었다. 실제 2MB 전후 조각이 계속 수신되는 중에도 중단되었다. 헤더 대기 제한과 본문 읽기 유휴 제한을 분리했다. 본문은 다음 조각 데이터가 30초 동안 오지 않을 때 reader를 취소하고 기존 재시도 경로를 사용한다. 호출자의 취소 신호는 계속 fetch에 연결된다.

## 실제 Chrome 전송 검증

- 사용자 브라우저와 분리한 임시 Chrome 프로필과 확장 복사본을 사용했다. 테스트 복사본의 호스트 권한은 진단용으로만 확대했으며 원본 manifest 권한을 확대하지 않았다.
- 사이트의 외부 개발 도구 감지 스크립트만 진단 프로필에서 차단했다. 원본 재생목록·키 응답·조각 본문은 수정하지 않았다.
- `artifacts/tvmon/run-1794204285506/report.json`: 13개 CDN에서 조각 15개를 전송·복호화하여 31,754,516바이트를 확정했다. 완료한 조각 중 3개는 30초를 넘었고, 가장 오래 걸린 조각은 약 150.2초였다. 전체 원본 재생목록은 1,951개 조각이다.
- 이 실행의 MP4 브라우저 저장은 진단 도구가 잘못 지정한 다운로드 경로로 인해 `FILE_FAILED`가 발생했다. 이를 제품 다운로드 성공으로 집계하지 않았다.
- 다운로드 디렉터리 생성 및 Windows 네이티브 경로를 적용한 최종 실행: `artifacts/tvmon/run-1794204697477/report.json`. 원본 재생목록을 그대로 사용하고 기존 중지 후 저장 제어로 부분 파일을 만들었다. 조각 5개, 복호화 후 9,919,632바이트, Chrome 다운로드 상태 `complete`, 저장 MP4 9,674,004바이트였다.
- 저장 파일은 10.0478초이며 AVC 1920×1080 영상 패킷 240개와 AAC 음성 패킷 471개를 포함한다. 실제 Chrome에서 처음·중간·끝을 탐색한 결과 영상과 음성 바이트가 모두 디코딩되고 미디어 오류가 없었다. 별도 검증 결과는 같은 실행 폴더의 `file-validation.json`에 보관했다. 전체 65분 다운로드 검증으로 확대하지 않는다.

원시 서명 쿼리, 재생 세션 값, 실제 키 응답은 Git에서 제외한 `artifacts/tvmon/`에만 있다. 회귀 fixture는 `00`부터 `0f`까지의 합성 키이며 실제 서비스 키를 포함하지 않는다. 다양한 노이즈 길이·비항등 순열을 사용한 fixture와 실제 관측 응답 모두 공개 플레이어의 역변환 결과와 대조했다.

## 자동 검사

- `node --test tests/*.test.mjs`: 총 756개, 통과 755개, 실패 0개, 건너뜀 1개. 최종 로그: `artifacts/tvmon/tests-final.log`.
- `node --expose-internals tools/checks/verify-project.mjs`: JavaScript 370개, JSON 19개, 상대 import 862개, 로컬 참조 138개, 보존 파일 84개, 실패 0개. 로그: `artifacts/tvmon/check-final.log`.
- 요청 문맥, credential 범위, fMP4 응답 문맥, 전체 Referer 비전파, JSON 키 정상·오류 응답, 진행 중인 장시간 본문·정체·헤더 시간 초과·외부 취소를 검사했다. 별도 코드 검토에서 확인한 fMP4 문맥 누락을 수정하고 회귀 테스트를 추가했다.
- 중간 전체 검사에서 병행 변경 중인 Explorer 호스트 capability 테스트가 한 차례 실패했고 재실행에서 통과했다. 이후 이번 리소스 문맥 캐시가 기존 HLS 반복 응답에 불필요한 쓰기를 추가하는 회귀를 발견하여 수정했다. 위 수치는 두 실패를 해결·재확인한 후의 전체 실행 결과다.

## 적용

로컬 `extension/`을 로드한 Chrome에서 MDownloader를 새로고침한 뒤 대상 페이지도 다시 열어야 새 요청 관측기가 적용된다. 사이트 및 재생목록·조각 CDN의 호스트 접근 권한은 기존 절차대로 필요하다. 전체 65분 파일의 저장 완료와 사용자 브라우저 세션은 이번 부분 전송 검증에 포함하지 않는다.

## 0 B/s 표시 및 실제 사이트 속도 재검증

사용자가 0%·0 B/s 정체를 보고하여 저장 가능 여부와 별도로 실제 전송 속도·초기 진행 표시를 검사했다.

- 확장 프로그램을 로드하지 않은 Chrome에서 원래 TVMON 페이지와 외부 플레이어를 열고 실제 HTTP 미디어 응답을 측정했다. `artifacts/tvmon/site-speed-1794206504151/results.json`: 2,425,024바이트/1.254초, 1,349,472바이트/9.016초, 2,152,608바이트/14.978초. 모두 HTTP 200이며 약 1.93, 0.15, 0.14 MB/s였다. 로딩 시간을 전송 속도로 계산하지 않았다. 네 번째 응답은 검사 종료 시 완료되지 않았으므로 완료 표본에 포함하지 않았다. 초기 도구의 종료 중 pending 응답 예외는 도구에서 처리했다.
- 두 번째 실제 사이트 검사 `artifacts/tvmon/site-speed-1794207352070/results.json`에서도 확장을 로드하지 않았다. 1,741,824바이트는 5.145초, 1,349,472바이트는 8.107초에 완료됐다. 앞선 검사에서 1.254초에 끝났던 2,425,024바이트 조각의 새 요청은 약 0.822초에 HTTP 200 헤더가 왔지만, 전체 관측 181.8초 동안 본문 완료를 확인하지 못했다. 검사 종료에 따른 취소/본문 읽기 오류와 서버의 HTTP 실패를 구분했다. 접속 시점별 편차가 큰 HTTP 경로이며 항상 일정한 다운로드 속도라고 평가하지 않는다.
- 같은 미디어 조각의 탐색적 60초 측정은 요청 4개에서 13,849,674바이트, 2개에서 7,042,402바이트였다. `artifacts/tvmon/benchmark-1794206630483/results.json`. 일부 다른 진단 요청과 시간대가 겹쳤으며 CDN의 시점별 편차도 커서 이 값을 통제된 배속 개선이나 항상 같은 속도를 보장하는 근거로 사용하지 않는다. 별도 2개 요청의 긴 실행은 368.4초에 약 27.5MB를 받았으나 한 응답은 시간 초과였다.
- 암호화 조각은 이전에 전체 수신·복호화·쓰기 이후에야 진행량을 보고했다. 이제 제한된 메모리에서 받는 암호문 바이트를 임시 수신량으로 표시하고, 평문 쓰기로 전환할 때 임시량을 제거한다. 실패·취소에서도 차감하며 검증하지 않은 암호문을 파일에 쓰지 않는다.
- HLS 조각 1/1,951이 정수 내림으로 0%가 되는 문제를 수정하여 0.05%로 표시한다. 완료 전 99% 상한은 유지한다.
- 여러 서버를 선언한 큐는 기존 일반 전송 상한 4개를 사용한다. 하나의 관측 서버만 쓰는 큐는 2개 제한을 유지한다.
- `artifacts/tvmon/engine-speed-1794207172680/results.json`: 기존에 관측한 재생목록을 첫 13개 조각으로 제한하고 실제 원래 CDN·키 URL을 그대로 요청한 전송 전용 검사다. 탐지나 전체 회차 검증으로 취급하지 않는다. 첫 바이트 진행은 0.723초에 보고됐다. 29.84초에 임시 수신량 포함 14,319,919바이트였고, 30초에 중지 후 저장을 요청했다. 진행 중인 느린 요청을 끝낸 뒤 9개 조각을 정상 MP4 18,393,276바이트로 저장했다. 18.0475초, AVC 1920×1080·AAC이며 Chrome에서 처음·중간·끝의 영상·음성 디코딩을 검사했다. `file-validation.json`에 결과가 있다.
- 실제 페이지의 새 네트워크 관측을 기존 스캔 캐시에 넣어 전송 경로에 집중한 별도 실행에서도 작업 생성 2.634초에 수신량이 보고되었다. `artifacts/tvmon/run-1794206920771/report.json`. 이 실행은 스캔 단계 우회 여부를 명시했으며 실제 페이지·재생목록·키·조각 본문은 바꾸지 않았다.
- 위 실제 작업은 진행량 샘플 300개에서 수신이 계속 보고됐고, 최종 관측은 약 37.2MB·완료 조각 17개였다. 중지 후 저장을 요청한 뒤에도 느린 진행 중 요청이 남아 진단 제한 시간에 브라우저를 종료했다. 이 실행을 저장 완료나 전체 회차 속도 검증으로 집계하지 않았다. 저장·재생 완료 근거는 앞의 전송 전용 검사에 한정한다.
- 사용자 Chrome의 MDownloader 로드 경로는 확장 설정에서 `E:\Project\MDownloader\extension`임을 읽기 전용으로 확인했다. 사용자 브라우저 설정은 변경하지 않았다.

최종 자동 검사: `node --test tests/*.test.mjs` 총 759개, 통과 758개, 실패 0개, 건너뜀 1개. 로그는 `artifacts/tvmon/tests-speed-final.log`다. 프로젝트 정적 검사는 JavaScript 371개, JSON 19개, 상대 import 865개, 로컬 참조 138개, 보존 파일 84개, 실패 0개다. 임시 수신량·오류 롤백·복호화 후 중복 집계 방지·전송 4개 상한·첫 조각의 소수 진행률을 검사하고 별도 코드 검토를 수행했다.

이미 진행 중인 작업에는 이전 실행 문맥이 남을 수 있다. 해당 작업을 취소하고 확장을 새로고침한 뒤 원래 페이지도 다시 열어 새 항목으로 시작한다. 진행 표시 개선과 여러 CDN의 동시 처리 확대는 사이트 서버나 네트워크 경로의 대역폭을 보장하지 않는다.
