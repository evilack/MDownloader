# BIGO HLS download failure — 2026-11-09

## Observed failure and cause

The reported page was `https://www.bigo.tv/165253945`. The user confirmed that the live video was playing and supplied the detected M3U8 URL on `45a088a9.cubetecn.com:1454`.

A direct request returned HTTP 200 with a normal live media playlist plus `#EXT-X-BIGO-WEB-PROTECTION:VERSION=1,SEED=3142190640`. Its first downloaded TS segment contained 256,244 bytes (1,363 packets). Only the sync bytes of its first two packets were wrong; the remaining packet sync bytes were valid. The previous downloader ignored the custom tag and rejected the bytes with `stream_invalid_mpeg_ts` before committing a segment.

The protocol was checked against BIGO's actual [public web player loader](https://static-act.da7akni.net/live/assets/www_bigo_tv/client/14.37bf41.js), webpack module 1444, downloaded during this investigation. It uses a public playlist seed to restore the first 16 bytes of each of the first two TS packets with a per-packet xorshift32 mask. This is independent of HLS AES keys. No login credentials, playback control methods, license service, or DRM path were used.

An isolated logged-out page returned `needLogin: true` with no stream URL. This describes the test browser, not the user's playback state. The user-supplied media endpoint was therefore used for the actual media inspection. Later in the investigation that endpoint returned HTTP 404. This is not evidence that the user's current broadcast had ended.

## Change

- `extension/lib/hls.js` validates the version and nonzero uint32 seed, attaches the descriptor to each segment, and keeps each live refresh's seed separate. It rejects duplicate or malformed declarations, protection on master playlists, and unsupported combinations with keys, initialization maps, byte ranges, or partial segments. Finite observation capture also receives the descriptor and strips the custom tag from its local playlist.
- `extension/lib/hls-encryption.js` restores an input copy before TS validation and scratch-file commitment. The existing shared resource decoder also serves thumbnails, hover previews, and observation capture. Protected responses retain the existing size bounds and cancellation behavior. Unknown versions or corrupted output fail closed.
- Normal clear and AES-encrypted HLS paths retain their previous behavior.

They then passed with the fix.
