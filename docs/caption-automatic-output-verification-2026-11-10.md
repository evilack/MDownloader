# 음성 자막 자동 출력 검증 — 2026-11-10

## 요청과 수정

정상 음성 인식 작업에 별도의 ‘라이브 자막 파일 저장’ 버튼, 저장할 파일 선택 대기 문구, 임시 인식문 영역이 표시됐다. 기존 동시 인식 경로는 최종 출력 설정과 별도로 라이브 파일 내보내기를 시작했고, 그 작업을 마무리하는 과정도 최종 처리 경로에 포함했다. 사용자가 선택한 자막 포함 영상/SRT/VTT를 자동 저장하는 흐름에 불필요한 작업이었다.

- `extension/local-captions-job.js`, `local-captions.css`: 정상 진행 상태와 최종 출력 이름만 표시한다. 라이브 파일 선택, 임시 인식문, 관련 설명은 제거했다. 실제 실패 시 재시도/설정 동작은 유지한다.
- `extension/lib/concurrent-captions-runner.js`: 정상 작업의 라이브 파일 작성 및 임시 인식문 발행 경로를 제거했다. 확정 인식 구간, 병합, 승인, 종료 및 최종 결과 처리는 유지한다.
- `extension/lib/local-captions-service.js`: 사용하지 않는 라이브 파일 연결/상태/발행 요청과 초기 정리 의존성을 제거했다. 이 작업에서 사용하지 않는 저수준 모듈까지 삭제하지는 않았다.
- 최종 출력은 다운로드별로 선택한 영상 내 자막, SRT, VTT 설정을 따른다. 추가 자막 파일 선택을 요구하지 않는다. 다운로드 저장 위치를 정하는 기존 동작과는 별개다.

## 실제 엔진 검증에서 발견한 추가 문제

AAC MPEG-TS의 구간 마지막 패킷 길이 추정과 90 kHz 타임스탬프 반올림이 처리 오디오 샘플 하나의 겹침으로 보이는 경우가 있었다. `hls-capture-clock.js`와 `hls-capture-source.js`는 동일 코덱 설정/불연속 구간/소스 샘플레이트를 가진 AAC TS의 서로 다른 세그먼트 경계에서만, 소스 샘플 및 PTS 정밀도 안의 정확히 한 처리 샘플 겹침을 정규화한다. 원본 패킷 시간은 보존한다. 실제 겹침, 더 큰 겹침, 다른 포맷 및 양의 간격은 허용 범위를 넓혀 처리하지 않는다.

실제 디코더의 오디오가 인식 창에 필요한 범위를 채우지 못하는 별도 경우도 확인했다. 테스트의 32초 TS 입력에서는 요구 끝 샘플 448000에 비해 실제 디코딩 끝이 446567이었다. 이 상태를 성공한 창으로 처리하지 않는다. `caption-output-pipeline.js`는 확인된 `caption_window_guard`, `stream_capture_clock_overlap`, `caption_seam_unresolved`에 한해, 해당 작업 소유의 완성된 AV 입력이 있고 아직 최종 출력/저장 영수증이 없을 때 기존 시도를 종료 확인한 뒤 새 시도로 최종 AV의 음성을 처리한다. 다른 오류나 취소, 종료 확인 실패에는 적용하지 않는다. 네이티브 도우미가 처리 순서나 대체 경로를 결정하지 않는다.

도우미 소스/설치본, 모델, 사용자 기본 설정은 이 수정에서 변경하지 않았다. 네이티브 개별 명령과 기존 타임라인 정렬 기능을 사용했다.

## 재부팅 후 확인

Chrome 원격 디버깅 허용은 사용자가 직접 수행했다. 연결 후 설치된 확장이 `eaimflahgdgfehekmdefignmffapamjk`, 버전 `0.2.43`, 활성화된 unpacked 확장이며 경로가 `E:\Project\MDownloader\extension`임을 확인했다. 사용자 확장 재로드나 작업 취소는 실행하지 않았다.

실제 확장 페이지에서 현재 `CreateCaptionJobStatus` 모듈을 불러와, 이전 라이브 파일 대기/임시 인식문 상태를 포함한 읽기 전용 검사 입력으로 DOM을 생성했다. 표시 문구는 ‘음성 자막 · 다운로드 중 · 음성 인식 병행’, 버튼 0개, 라이브 요소 0개, 임시 검사 인식문 미표시, 빈 액션 영역 숨김을 확인했다. 검사 입력을 실제 다운로드 큐에 추가하지 않았다. 이는 설치된 모듈의 DOM 검사이며 재부팅 후 장시간 다운로드 재실행 결과는 아니다.

위 실제 파일의 크기와 MP4 트랙을 재확인했다. 홈페이지 프리뷰의 61개 소스 해시도 현재 소스와 일치했다. 프리뷰는 확장 컴포넌트를 사용하는 모의 데이터 화면이며 실제 다운로드/인식 백엔드가 아니다.

## 후속 수정: 실제 인식 단계별 표시

사용자의 후속 요청에 따라 여러 단계를 묶던 ‘음성 인식 병행’ 표시를 제거했다. 다운로드 중에도 `queued`는 ‘인식 대기 중’, `recognizing`은 ‘음성 인식 중’, `recognized`는 ‘자막 준비 완료’를 표시한다. 모델 로딩과 결과 정리는 각각 기존의 별도 문구를 유지한다. 동일 UI 인스턴스가 단계 변경을 반영하는 회귀 검사를 추가했고, 위 자동 검사 명령은 현재 34개 전부 통과한다. 홈페이지 프리뷰도 다시 생성했다.

설치된 확장의 다운로드 관리 페이지만 새로고침한 뒤 실제 모듈의 한국어 DOM 출력을 단계별 검사 입력으로 확인했다. 확장 전체/백그라운드는 재시작하지 않았다. 검사 시 표시 중인 자막 작업은 없어 새 실제 다운로드의 단계 전환까지 재현한 검증은 아니다.

## 검증 한계

검증한 실제 인식 입력은 짧은 로컬 음성 샘플이다. 모든 사이트/포맷, 장시간 동시 인식, 인식 정확도, macOS, 앱 재시작 후 기존 작업 복구를 검증한 결과로 확대하지 않는다. 특히 정상 32초 TS 두 건은 확인된 인식 창 오류 후 완성 AV를 처리해 완료했고, 중지 후 저장 두 모델 사례는 구간 인식으로 완료했다. 모든 입력이 다운로드 중 인식만으로 끝났다고 주장하지 않는다. 원격 게시/배포는 이 작업에서 수행하지 않았다.
