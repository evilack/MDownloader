# WebRTC 서버 화질 선택 — 0.2.27

사용자 요청: 기존 영상 항목의 다운로드 버튼을 사용하고, Shift+다운로드 때 기존 화질 선택창으로 서버 수신 화질을 고른다. 다운로드 관리자의 기존 녹화·진행률·저장 종료·취소 경로를 유지한다. Windows 컴퓨터 사용은 수행하지 않는다.

## 동작

- 일반 클릭은 현재 수신 트랙을 저장한다.
- Shift+클릭은 해당 트랙과 연결된 실제 서버 프로필을 기존 행 아래 화질 창에 표시한다. 하나뿐인 WebRTC 프로필도 선택창에 표시한다. HLS의 단일 프로필 자동 등록은 기존대로 유지한다.
- `blurred` 프로필은 제외한다. 지원 프로필이 관측되지 않은 경우 새로고침 안내를 표시하며 화질을 만들어 내거나 현재 화질로 조용히 대체하지 않는다.
- 선택 후 기존 시그널링 소켓으로 `changeQuality`를 보낸다. 서버의 `changeQualityStatus` 성공 응답과 실제 videoWidth/videoHeight가 모두 맞아야 MediaRecorder를 시작한다.
- 녹화 중에만 해당 서버 프로필을 유지한다. 자동 화질 요청의 원래 의도를 보존하고, 종료·취소·실패 때 플레이어 제어로 돌린다. 수신 해상도가 선택과 달라지면 부분 저장으로 종료한다.
- 화질 변경 전 문서의 녹화 슬롯을 requestId/token으로 예약한다. 다른 녹화나 동시 요청은 서버 화질을 바꾸기 전에 거절한다. 준비 단계의 저장 종료는 아직 조각이 없으므로 시작을 취소한다.
- 선택한 작업의 미리보기는 전환 이후에 수집한다. 이전 720×960 이름을 240p 작업에 붙이지 않도록 선택 작업의 기본 이름은 WebRTC.mp4이며 실제 저장 확장자는 녹화 MIME으로 결정한다.

## 실제 서버 관측

방송 서버는 다음 프로필을 반환했다. 중간 프로필의 크기는 인코더의 최대 상자이며, 세로 원본의 비율을 유지한 실제 수신 크기는 다르다.

| 서버 프로필 | 서버 최대 크기 | 실제 수신 확인 | 서버 비트레이트 메타데이터 |
| --- | --- | --- | --- |
| 240p | 426×240 | 180×240 | 500,000 bps |
| 480p | 720×480 | 360×480 | 1,100,000 bps |
| source | 720×960 | 720×960 | 약 1,831,840 bps |

서버 메타데이터의 비트레이트는 선택창 설명에 사용하며 실제 파일의 인코딩 비트레이트를 보장하지 않는다. MP4/WebM 저장은 기존 수신 트랙 복제 및 MediaRecorder 경로를 사용한다. 별도 페이지나 임의 리사이즈 화질 선택을 추가하지 않았다.

## 구현과 상태 경계

`webrtc-quality-observer.js`는 승인된 호스트의 document_start MAIN 관측기로 등록된다. 실제 원격 SDP의 ice-ufrag/fingerprint 묶음으로 소켓 세션과 PeerConnection을 연결하고, receiver의 정확한 트랙 ID로 목록을 한정한다. SDP, 인증 패킷, 소켓 주소 및 서버 mediaSessionId는 확장 메시지·저장소·진단 로그로 내보내지 않는다. UI에는 임의 세션 식별자와 프로필 정보만 반환한다.

녹화 소유권은 ISOLATED 월드에, 서버 화질 제어는 MAIN 월드의 제한된 임대에 둔다. 먼저 도착한 취소도 임대를 폐기하여 지연된 select가 다시 활성화되지 않도록 한다. 녹화 heartbeat가 임대를 갱신하며 갱신이 끊기면 자동 해제한다. 원래 WebSocket/PeerConnection의 반환·예외 계약은 유지한다.

## 검증 범위와 남은 확인

- Node 전체 216개 테스트 통과. 기존 HLS Shift 선택, WebRTC 동일 선택창, 단일 프로필, 취소, 슬롯 예약과 소유권, 기존 녹화 중 두 번째 요청, 선택 중 취소, 선행 취소, 서버 실패 및 트랙/세션 변경을 포함한다.
- 프로젝트 검사: JavaScript 164개, JSON 16개, 상대 import 432개, 로컬 참조 98개, 보존 파일 73개, 실패 0.
- 현지화: 10개 언어 × 373개 메시지, 누락 참조 0, UI 문자열 후보 0. 페이지 정책 생성물 일치 검사 통과.
- 별도 읽기 전용 코드 리뷰에서 서버 전환 전 예약 누락을 찾아 수정했다. 재검토에서 Important 이상의 잔여 문제는 보고되지 않았다.
- 실제 Chrome의 기존 방송 세션에서 서버 성공 응답과 180×240, 360×480, 720×960 수신 전환을 확인했다. 첫 실험은 최대 상자와 실제 세로 수신 크기가 달라 안전하게 실패했으며, 이후 원본 비율 계산을 반영했다.
- 브라우저 도구는 document_start 개발용 주입 명령을 지원하지 않았다. 실제 전환 시험에는 현재 소켓/PeerConnection을 DevTools로 조회하고 기존 시그널링·원격 SDP를 개발용 관측 상태에 연결했다. 개발용 상태의 중간 프로필 크기도 실측 비율로 맞췄다. 따라서 이 시험은 서버 전환과 수신 크기의 근거이며, 설치된 0.2.27의 document_start 초기화나 전체 UI 저장 완료를 검증한 것은 아니다. 초기 연결의 소켓/SDP/receiver 연결과 비율 계산은 단위 테스트로 확인했다.
- 개발용 변경은 영상 페이지 새로고침으로 제거했고 원본 크기 재생을 확인했다. 로컬 검증 서버는 종료했다. Windows 앱/키보드/마우스 조작은 사용하지 않았다.
- **설치된 확장 0.2.27의 새로고침 및 영상 페이지 새로고침 후 실제 Shift 창/다운로드 관리자/최종 파일을 확인하는 단계는 아직 남아 있다.** 브라우저 도구의 확장 관리 화면 접근 제한 때문에 사용자의 확장 새로고침이 필요하다.
