# Facebook·Instagram 릴 URL 과다 표시 수정 검증

2026-11-09, 요청받은 두 게시물의 감지 및 다운로드 경로를 확인했습니다.

- Facebook: `https://www.facebook.com/reel/1824177091898417?locale=ko_KR`
- Instagram: `https://www.instagram.com/reels/DfCSasTh1nR/`

## 원인과 변경

Facebook의 실제 재생 요청에서 영상과 음성이 별도의 MP4 리소스에 있고, 각 리소스의 초기화·미디어 구간을 `bytestart`·`byteend` 쿼리로 요청하는 것을 확인했습니다. 기존 감지는 각 구간을 완전한 MP4 후보로 분류했습니다. 범위 쿼리를 제거하는 것만으로는 분리된 영상·음성을 합칠 수 없습니다.

Meta CDN의 해당 MP4 범위 요청은 독립 파일 감지와 기존 캐시 표시에서 제외합니다. 현재 게시물 ID가 일치하는 선언 데이터에서 전체 MP4를 선택합니다. Facebook은 `videoDeliveryLegacyFields`의 HD/SD 주소, Instagram은 `shortcode`/`code`가 일치하는 `video_url` 또는 가장 큰 `video_versions`를 사용합니다. 서명된 전체 파일 URL은 수정하지 않습니다.

Instagram의 SPA 이동으로 현재 게시물 데이터가 DOM에 없을 때는 같은 출처의 해당 게시물 공개 임베드 HTML을 제한된 크기·시간 안에서 읽습니다. JSON만 해석하며 스크립트는 실행하지 않습니다. 다른 게시물, 다른 문서, 다른 탭의 결과를 섞지 않습니다. 진행 중 조회는 공유하고 성공 결과는 최대 64개·30초 동안 재사용합니다.

현재 게시물의 전체 파일이 확인되면 최상위 문서의 Meta CDN 후보를 그 파일로 정리합니다. 다른 문서의 관측 및 다른 시간 원점에서 수집된 하위 프레임 재생목록은 유지합니다.

## 실제 Chrome 확장 검증

별도 새 프로필의 Chrome 157.0.8103.39에 원본 확장의 복사본을 로드했습니다. 검증 복사본에만 필요한 호스트 권한을 부여했으며, 사용자의 일반 Chrome 프로필이나 로그인 상태는 변경하지 않았습니다. Computer Use는 사용하지 않았습니다.

`Scan → ResolveCandidate → enqueue` 메시지 → 실제 Chrome 다운로드 경로로 확인했습니다. 파일의 ISO BMFF 구조에서 영상(`vide`)·음성(`soun`) 트랙을 확인하고, 저장된 바이트를 Chrome 영상 요소에서 재생했습니다.

Instagram 일반 릴 주소는 새 프로필에서 로그인 화면으로 이동했습니다. 따라서 로그인한 일반 릴 화면의 네트워크 과다 감지는 직접 재현하지 못했습니다. 공개 임베드에서 실제 전체 파일을 확인했고, 일반 릴의 동일 출처 임베드 대체 조회는 회귀 테스트로 검증했습니다. Facebook은 일반 릴 페이지에서 실제 범위 요청 7개가 발생했어도 후보가 1개였습니다.

실행 증거는 Git 제외 경로 `artifacts/facebook-reel/live-1794194309585/report.json`에 있습니다. 원시 응답 및 서명된 CDN 주소는 Git 문서에 포함하지 않습니다.

## 추가 수정: Facebook 후보 누락과 Instagram 해상도 표시

사용자 재확인에서 Facebook 후보가 보이지 않고 Instagram 미리보기에 해상도가 없는 문제가 보고되었습니다. 다음은 앞선 검증을 보완하는 최신 결과입니다.

Instagram은 선택한 전체 파일의 `video_versions.width/height` 또는 `video_url`과 같은 객체의 `dimensions`를 추출하지 않고 있었습니다. 해당 값을 후보에 전달하도록 수정했습니다. 기존 미리보기의 후보 해상도 보충 경로를 사용하므로 Blob 플레이어와 직접 연결하지 못해도 표시할 수 있습니다.

Facebook은 릴 내부 이동 후 현재 문서에 영상 메타데이터가 없는 상황을 재현했습니다. 일반 `/reel/{id}/` HTML을 다시 읽어도 영상 주소 없이 페이지 골격만 반환되는 것도 실제 Chrome에서 확인했습니다. 따라서 현재 출처의 공개 `/plugins/video.php?href={정확한 릴 URL}`을 읽도록 수정했습니다. 응답의 `VideoConfig.videoData` JSON 배열에서 게시물 자체의 `video_id`가 일치하는 `hd_src`/`sd_src`를 선택합니다. 괄호·인용부호·이스케이프를 구분해 JSON 배열만 해석하며 ServerJS 코드는 실행하지 않습니다. 독립 legacy 레코드도 정확한 ID 아래에서 허용하고, 무관한 런타임 스크립트는 메타데이터 파싱 예산을 소모하지 않도록 했습니다.

이번 실제 Chrome 검증은 **원본 manifest의 권한을 그대로 유지**했습니다. 호스트 권한이나 `tabs` 권한을 추가하지 않았습니다. 실제 확장 툴바 동작으로 `activeTab` 접근을 부여한 뒤 실제 팝업을 검사했습니다.

- Facebook: 현재 문서의 스크립트 데이터를 제거한 후 툴바 버튼을 실행했습니다. 일반 페이지 HTML에 `browser_native_hd_url`이 없는 상태에서도 실제 팝업 후보 1개가 표시됐고, 정상 작업 등록과 전체 MP4 다운로드가 완료되었습니다.
- Instagram: 같은 게시물의 공개 임베드에서 실제 팝업의 해상도 라벨이 **720×1280**으로 표시됐습니다. 미리보기 API도 동일한 크기를 반환했으며 전체 MP4 다운로드가 완료되었습니다. 새 프로필의 일반 릴 주소가 로그인을 요구한다는 앞선 제한은 그대로입니다.
- 두 파일은 이전과 동일한 크기와 영상·음성 트랙을 가지며 Chrome에서 재생됐습니다.
- Meta 회귀 테스트 16개, 관련 감지·네트워크·미리보기·표시 테스트 총 62개가 통과했습니다.
- 추가 전체 테스트 재검사는 643개 중 **642개 통과, 1개 건너뜀, 실패 0개**였습니다. 위 최초 실행 당시의 HLS 테스트 실패는 이 최신 실행에서는 발생하지 않았습니다.
- 실제 팝업 캡처와 실행 보고서는 Git 제외 경로 `artifacts/facebook-reel/live-1794195185280/`에 있습니다. `facebook-popup.png`, `instagram-popup.png`, `report.json`을 확인했습니다.
- 개발용 배포 폴더를 다시 갱신했습니다.

## 추가 수정: 실제 재생 프레임의 썸네일 갱신

사용자가 Facebook 해상도·썸네일과 Instagram 썸네일이 갱신되지 않는 것을 확인하여 실제 재생 중인 상태로 다시 검사했습니다.

- 전체 MP4 후보 주소와 페이지의 재생 주소가 달라 기존 썸네일 수집에서 플레이어를 연결하지 못했습니다. 현재 게시물의 `sourceIdentity`, 페이지, 문서가 일치하는 Meta 후보에만 현재 화면의 단일 플레이어 연결을 허용했습니다. 일반 카드와 다른 공급자의 제외 규칙은 유지합니다.
- Facebook의 실제 표시된 플레이어가 `aria-hidden` 상위 요소 안에 있었습니다. Meta 후보는 화면 교차 영역·계산된 표시 상태·상위 요소의 투명도와 게시물 소유권으로 확인합니다. 오프스크린 프리패치, 숨은 요소, 복수의 표시 플레이어는 보충 연결에 사용하지 않습니다.
- Instagram은 실제 재생 중인 영상의 Canvas 내보내기가 `Tainted canvases may not be exported`로 거절됐고 고정 포스터만 반환했습니다. 이 경우 현재 활성 탭의 정확한 영상 표시 영역만 네이티브 캡처에서 잘라 작은 JPEG로 반환합니다. 탭·문서·페이지·재생 소스·화면 크기·영상 위치를 캡처 전후에 다시 확인합니다. 별도 대화상자·댓글 패널이 가린 영역은 제외합니다. 전체 페이지 이미지는 저장하거나 미리보기 응답으로 반환하지 않습니다. 새 권한은 추가하지 않았습니다.
- 기존 15초 썸네일 갱신과 공유 캐시 만료 경로를 사용합니다. 현재 프레임을 읽을 수 없을 때는 기존 표지/이미지를 유지합니다.

실제 원본 manifest와 툴바 activeTab 동작으로 팝업을 열고, 첫 썸네일과 주기 갱신 후 썸네일을 각각 캡처·검수했습니다.

| 대상 | 해상도 표시 | 첫 이미지 → 갱신 이미지 | 증거 |
| --- | --- | --- | --- |
| Facebook 일반 릴 | 360×640 | 서로 다른 실제 영상 프레임으로 갱신 | `artifacts/facebook-reel/live-1794197749865/` |
| Instagram 동일 게시물 공개 임베드 | 720×1280 | Canvas 차단 상태에서도 서로 다른 실제 영상 프레임으로 갱신 | `artifacts/facebook-reel/live-1794198026329/` |

Facebook의 360×640은 검사 당시 페이지가 디코딩하던 재생 화질입니다. 전체 다운로드 파일의 720×1280과 구분합니다. Instagram 일반 릴 URL은 새 검사 프로필에서 로그인 화면으로 이동하므로 같은 게시물의 공개 임베드에서 재생 버튼을 누른 뒤 검증했습니다.

각 증거 폴더의 `*-thumbnail-first.png`, `*-thumbnail-refreshed.png`, `report.json`에 표시 상태, 해상도와 서로 다른 썸네일 해시를 기록했습니다. Facebook·Instagram 이미지 전후를 실제로 확인했습니다. 마지막 Instagram 실행은 네이티브 플레이어 컨트롤을 허용하면서 별도 가림 UI를 제외하는 최종 검증 조건으로 통과했습니다.

관련 테스트 54개 통과, 전체 테스트 **681개 중 680개 통과·1개 건너뜀·실패 0개**입니다. 페이지 이동·소스 변경·숨은 플레이어·복수 플레이어·투명 상위 요소·가림 UI·캡처 좌표 배율·캐시 만료 후 프레임 갱신을 회귀 검사했습니다.
