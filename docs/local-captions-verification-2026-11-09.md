## Native engines and output

`tools/checks/probe-local-captions.mjs` connects the production caption service and native RPC client to a real Python host over Chrome-compatible length-prefixed JSON. It uses a generated MP4 containing synthesized English speech and verifies SRT/VTT files saved beside it. Windows CPU tested faster-whisper 1.2.1 / PyAV 15.1.0 and whisper.cpp's official b5454 x64 build, both with Tiny. PyAV 19.0.2 was observed incompatible with this faster-whisper version (`metadata_errors` argument), so installation pins the working version. NumPy import in a worker concurrent with Windows stdin read was observed to hang; the native entry point initializes optional engine libraries before reading the protocol. The same actual entry point then completed the protocol tests.

The tests do not claim general transcription accuracy: the Tiny models made word errors in the synthetic sample. No real-video accuracy, long-video performance, GPU, macOS or Metal benchmark is claimed. Models/binaries downloaded for these checks are isolated under ignored `artifacts/`; the user helper was not registered and its initial model set remains empty.

## Clock and preparation

The streaming regression verifies that a complete finite audio track is offered for preparation while later video segments are still downloading, only after its first video reference is committed. Preparation failures fall back to the saved media. Partial/live output does not reuse an incompatible full-length preparation.

An actual delayed-audio fMP4 HLS fixture showed independent HLS audio normalization removed its relation to the video clock. The implementation therefore carries only the first committed video prefix with the prepared audio as a clock reference. FFmpeg removes that video and retains any leading audio gap when preparing WAV. `tools/checks/probe-caption-audio.mjs` compared prepared and final packet clocks: both audio starts were 1.753015873015873 seconds, with a difference of 0. SRT/VTT offset clipping/rounding is separately covered by native tests.

## Automatic setup follow-up

Both helpers now use a single extension Install action: download → execution request → actual native connection check. Explorer closes its gate and continues the folder picker when connected, with no Run/Continue button in the normal path. Connection timeout, blocked download, canceled pending open and a host that never replies are tested. Open API success never counts as successful installation. The payload is prefetched and downloads.open is required at extension installation rather than requested as a new optional step on the helper button.

The caption installer automatically downloads checksum-pinned uv, prepares private Python3.12 and binary engine dependencies, verifies the actual generated native launcher and engine responses, then registers. The isolated Windows bootstrap used no preinstalled Python command or global pip/PATH changes, and no models directory was created. It completed both faster-whisper and whisper.cpp probes. An ASCII-only CMD launcher based on %~dp0 also passed the same real framed probes from a Korean installation path containing spaces. The whisper.cpp binding worker transcribed the existing isolated sample successfully. No test registered or overwrote the user's caption host.

`tools/checks/probe-caption-installer.mjs` additionally executed the generated self-extracting CMD. Only the destination and NoRegister arguments were overridden; payload decoding, hash validation, bootstrap, runtime/dependency downloads and actual launcher verification ran. It passed with both engines ready and no models (artifacts/caption-installer-wrapper-1794199750013/result.json). This exposed and fixed Windows PowerShell5 module-path conflicts inherited from PowerShell7; both generated helper wrappers now prepend Windows' own module directory in their child process. The Windows bootstrap uses built-in curl with bounded network timeouts, with Invoke-WebRequest as fallback, avoiding the observed Windows PowerShell5 download stall. This direct CMD test is distinct from the still-unverified browser-to-OS launch.

The macOS artifact is a scripts-only flat PKG containing the pinned bootstrap and ID-bound postinstall. Tests parse XAR, inflate its table, decode its gzip/newc Scripts archive, assert executable modes and required sources, and reject tampered payload hashes. Windows bsdtar also lists PackageInfo and Scripts. This is package structure verification; macOS Installer acceptance, postinstall and engine execution remain unverified.
